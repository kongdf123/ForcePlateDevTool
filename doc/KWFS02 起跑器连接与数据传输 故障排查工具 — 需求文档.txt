KWFS02 起跑器连接与数据传输 故障排查工具 — 需求文档
基于对系统架构（Communicator / SocketLinker / Decoder_76B_StartingBlock / DeviceCaptureSession）的分析，本工具需覆盖从物理链路到物理量输出的全链路诊断能力。

1. 背景与目标
1.1 背景
现场工程师经常遇到「设备连不上」「连上但没数据」「数据乱跳/全零」「时间戳异常」等问题。当前排障依赖日志 + Wireshark + 手工算字节，门槛高、耗时长。

1.2 目标
提供一个独立的可视化诊断工具，能在不依赖正式采集流程的情况下，逐层验证：

物理连接 → Socket 连接 → 命令交互 → 原始字节 → 帧解析 → 物理量转换
每一层都给出 PASS / FAIL / WARNING 及可读原因。
1.3 非目标
不替代正式采集软件（不做数据存储、曲线回放、测试报告）。
不修改设备固件。
不支持除 KWFS02（76B 起跑器）以外的设备（v1 聚焦单型号）。
2. 用户角色
角色	诉求
现场工程师	快速定位「连不上 / 没数据」的根因
研发支持	远程协助时让用户跑一遍诊断，导出报告
生产测试	产线批量校验设备通讯正常
3. 功能需求
3.1 连接配置层
F-101 连接参数录入

IP 地址（设备端默认 192.168.1.101，可改）
端口（默认 5152）
本地 IP / 端口（默认 192.168.1.100:8886）
采集模式：被动(48) / 主动(49) / 仅触发(58)
设备地址（默认 0xAA）
F-102 本地网卡探测

列出本机所有网卡的 IPv4，提示用户选择与设备同网段的网卡。
检测目标 IP 网段是否有匹配的本地网卡，若没有给出 WARNING。
F-103 物理链路预检

ping 设备 IP（3 次，超时 1s），显示丢包率 / 时延。
arp -a 校验设备 MAC 是否存在。
TCP 端口连通性测试（raw socket connect，超时 2s）。
3.2 Socket 连接层
F-201 建立连接

复用 SocketLinker.Open() 逻辑，显示连接耗时、本地/远端端点。
连接失败时分类报错：TimedOut / ConnectionRefused / NoRouteToHost / NetworkUnreachable，并给出建议（如「检查网线 / 设备是否上电 / IP 是否在同一网段」）。
F-202 连接状态监控

实时显示 TCP 连接状态（Connected / Disconnected）。
断线时自动提示，并支持一键重连。
3.3 命令交互层
F-301 起始命令发送

被动模式下发送 0x48 AA 0D 0A，显示发送字节（HEX）。
显示发送是否成功（写入字节数）。
F-302 停止命令发送

发送 0x48 AA 00 00 00 00 00 00 00 00 00 00 00 0D 0A。
F-303 命令历史

记录所有发送/接收的命令，带时间戳，HEX + ASCII 双视图。
3.4 原始字节接收层
F-401 原始字节流显示

实时滚动显示收到的原始字节（HEX），可调缓冲大小（默认 4KB）。
显示接收速率（字节/秒、包/秒）。
统计累计接收字节数、包数。
F-402 接收超时检测

若 10 秒内未收到任何字节，触发 ReceiveError 告警（与生产代码一致）。
显示最近一次接收时间。
F-403 帧头搜索

在原始字节流中高亮 0x48（帧头），便于肉眼判断是否有合法帧起始。
3.5 帧解析层
F-501 帧切分可视化

复用 DecoderBase.GetMapping() 逻辑，对原始字节流做帧切分。
显示：帧总数、完整帧数、残帧数、CRC/尾校验失败数。
每帧显示：[帧头 0x48][地址][72B 数据][0x0D 0x0A] 分段着色。
F-502 帧校验结果明细

对每一帧列出校验项：
✅ 长度 = 76
✅ 帧头 = 0x48
✅ 地址 ∈ {0xAA, 0xAB}
✅ 尾 = 0x0D 0x0A
任一失败标红并显示期望值 vs 实际值。
F-503 异常帧保留

校验失败的帧单独列出，保留原始字节，支持导出。
3.6 物理量解码层
F-601 18 个 float 实时值

按 ParseByteArray 把 72B 拆成 18 个 float，分左踏板(0xAA, index 0–8)、右踏板(0xAB, index 9–17)。
显示每个 float 的原始值和**×G 后的值**（GlobalValue.G = 9.8）。
标注每个值对应：传感器 S1/S2/S3 × 轴 X/Y/Z。
F-602 合力 / 力矩 / COP

复用 SensorData_76B_StartingBlock 计算 Fx/Fy/Fz/Mx/My/Mz/COPx/COPy。
实时数值 + 小型折线图（最近 100 点）。
显示 Az0（-22）参与计算的中间值。
F-603 零点偏移

支持「软件清零」：录制 200ms 求平均，显示每个通道的零点值。
清零前后数值对比。
3.7 采集模式专项
F-701 被动模式诊断

发送 StartCMD 后，检查 3 秒内是否有数据流入。
若无，提示「设备未推流，检查设备端是否配置为被动输出」。
F-702 主动模式诊断

发送 0x49 轮询命令，验证设备是否回复完整 76B 帧。
显示轮询周期、每轮回复耗时。
F-703 间接通讯检测

若设备配置了 IndirectConnect，提示「此设备为副台，需主台代收」，并检查主台地址是否可达。
3.8 报告与导出
F-801 诊断报告

一键生成诊断报告（PDF / HTML），包含：
连接参数
各层 PASS/FAIL 结果
异常帧样本
最近 100 点物理量统计（均值/最大/最小/标准差）
结论与建议
F-802 原始数据导出

导出原始字节流（.bin）
导出解码后的物理量（.csv，含时间戳）
4. 非功能需求
类别	要求
性能	原始字节流显示延迟 < 100ms；解码刷新 ≥ 50Hz
可用性	向导式「一键诊断」按钮，按层自动执行并汇总结果
可移植	独立 WPF / WinForms 工具，不依赖正式采集软件的运行环境
可扩展	解码器通过接口注入，后续可加 64B 力台、128B 跑台等型号
国际化	中/英双语（现场工程师为主中文）
5. 技术选型建议
UI 框架：WPF（与现有项目一致，可复用 SocketLinker / DecoderBase 源码）
架构：直接引用 KW.CommunicationLib 的 SocketLinker、DecoderBase、Decoder_76B_StartingBlock，不重复造轮子，保证诊断逻辑与生产一致
图表：LiveCharts2 或 OxyPlot（轻量）
网络诊断：System.Net.NetworkInformation.Ping + raw TcpClient
日志：复用 KW.LoggerService

7. 优先级（建议迭代顺序）
优先级	功能	理由
P0	F-103 物理链路预检、F-201 连接、F-301 起始命令、F-401 原始字节、F-501 帧切分、F-601 float 解码	覆盖「连不上 → 没数据 → 数据对不对」核心痛点
P1	F-602 合力/COP、F-603 零点、F-502 帧校验明细、F-801 诊断报告	提升定位精度，便于远程支持
P2	F-701/702/703 模式专项、F-802 数据导出、F-102 网卡探测	边界场景
P3	多设备型号支持、批量诊断	长期演进
8. 风险与注意事项
不要在生产环境运行：工具会发送 StartCMD 并占用设备端口，可能与正式采集冲突，需在工具顶部明显警告。
解码器一致性：诊断工具必须直接引用生产代码的 Decoder_76B_StartingBlock，避免两套解析逻辑不一致导致「诊断正常但采集异常」的误导。
大数据量性能：原始字节流显示需虚拟化，不能全量渲染（设备 1000Hz 时每秒 ~76KB）。
被动模式下不要误发停止命令：需明确告知用户停止命令会终止设备推流。
